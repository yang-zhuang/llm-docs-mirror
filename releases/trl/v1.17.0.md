## Features

### 🔥 Mistral Large 4: fine-tune a 1T-parameter model on one node

TRL now supports [`mistralai/Mistral-Large-4-1T-A52B`](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B): 1T parameters, 52B active. The new [LoRA example](https://github.com/huggingface/trl/tree/main/examples/sft_mistral_large_4) fine-tunes it with `SFTTrainer` **on a single 8×B300 node, on top of its FP8 weights**: the experts are split 8 ways with token dispatch, everything else is sharded across the 8 GPUs at load time by transformers' `DistributedConfig`, and LoRA trains attention and the dense and shared-expert MLPs.

Measured: **32.7k tokens per step in ~8 s, 142 GiB per GPU**, with packing and assistant-only loss on reasoning conversations.

### 🎯 Unbiased importance sampling under top-k, top-p and min-p

vLLM normalizes its log-probabilities over the tokens left after `top_k`, `top_p` and `min_p` filtering, while the trainer normalized over the whole vocabulary. Every sampled token's log-ratio was off by the log of the probability mass the filter kept, so the vLLM importance sampling ratio was biased towards 0 (around 1e-4 instead of 1 with `top_p=0.9`). The trainers now normalize over the candidate set each token was sampled from, following Keep Sampling Mask from [DeepSeek-V3.2](https://huggingface.co/papers/2512.02556).

* AsyncGRPO: renormalize log-probs over the top-k/top-p candidate set by @AmineDiro in https://github.com/huggingface/trl/pull/7627
* GRPO: renormalize log-probs over the top-k/top-p candidate set (vLLM colocate mode, vLLM >= 0.28; server mode will follow) by @albertvillanova in https://github.com/huggingface/trl/pull/7866
* Require `top_k` with `min_p` in AsyncGRPO so the importance sampling ratio stays unbiased by @albertvillanova in https://github.com/huggingface/trl/pull/7937
* Track the support maximum in the chunked log-prob kernel, so a far-below-max candidate set no longer gives a log-probability of 0 and non-finite gradients, by @kashif in https://github.com/huggingface/trl/pull/7983

**💥 What this changes for you.** vLLM bounds the candidate set it returns with `top_k`, so with vLLM and the importance sampling correction on (the default), `GRPOConfig` now raises when `top_p < 1.0` or `min_p > 0.0` is set without `top_k > 0`. Set `top_k` (e.g. `top_k=512`), or `vllm_importance_sampling_correction=False`.

### ⚖️ Score centering is the default AsyncGRPO objective

AsyncGRPO's old log-probs are the vLLM sampler's, so its ratio mixes staleness with the numerical mismatch between the server and the trainer. With an FP8 sampler and a bf16 trainer, the clipped objective collapses: reward goes from 0.60 to 0.34 (FP8 weights) or 0.10 (FP8 weights + KV cache) by step 300, against 0.71 with a bf16 sampler.

[Score centering](https://huggingface.co/papers/2609.20807) with masked importance sampling is now the default (`score_centering=True`, `importance_sampling_min=0.5`, `importance_sampling_max=5.0`). With it, the FP8 sampler trains exactly like the bf16 one (0.72). It costs 15–20% of generation throughput.

**💥 What this changes for you.** AsyncGRPO runs now train with a different objective by default, and tokens whose ratio to the sampler falls outside `[0.5, 5.0]` are dropped. Set `score_centering=False` to keep the clipped objective.

by @AmineDiro in https://github.com/huggingface/trl/pull/7760

### 🚀 Faster AsyncGRPO rollouts and packing

* **Adaptive in-flight cap from the vLLM load**: the rollout worker follows the server's KV cache usage instead of admitting a fixed `max_inflight_tasks`, so requests stop queueing and being preempted on the server. No new config: everything is read from the server. By @AmineDiro in https://github.com/huggingface/trl/pull/7610
* **Filter zero-advantage groups** (DAPO's dynamic sampling): groups whose rollouts all got the same reward, or none of which could be scored, no longer cost a forward and backward. By @AmineDiro in https://github.com/huggingface/trl/pull/7609
* **Pack the sampling mask ragged and pad it on the device**: `TreeRow.pack` goes from 250 s to 31 s on rank 0 over a 15-step run, and from 1040 ms to 66 ms on a 28k-token multi-turn row. By @AmineDiro in https://github.com/huggingface/trl/pull/7798
* Keep filling a micro-batch when another row has free room by @clementtisseau in https://github.com/huggingface/trl/pull/7793
* Use FlashAttention-4 on Blackwell GPUs in async GRPO and async distillation by @lewtun in https://github.com/huggingface/trl/pull/7792

### 🌳 Tree attention for linear-attention hybrids

Tree packing (v1.16) now supports the Gated DeltaNet hybrids: Qwen3.5, Qwen3.6, Qwen3-Next and OLMo-Hybrid. Since v1.16 the trainer refused them at init; before it, sequence packing accepted them but was silently wrong on them. The causal convolution and the delta-rule recurrence now follow the tree instead of the row, through FLA's chunked kernels.

by @AmineDiro in https://github.com/huggingface/trl/pull/7686

### 🎚️ Precise chunked log-probabilities

The chunked log-probability and KL/JSD heads get the two precision fixes from [A Fix for Softmax and Cross-Entropy](https://huggingface.co/papers/2610.31642): confident targets keep their small gradients, and matching teachers produce zero gradients. [Entropy-preserving reinforcement learning](https://huggingface.co/papers/2603.11682) (Appendix B.4) reports the same high-confidence policy-gradient issue.

* Fix chunked loss precision by @kashif in https://github.com/huggingface/trl/pull/7882
* Fix the fused log-prob/entropy backward on strided inputs (shifted views from SFT/DPO) by @winglian in https://github.com/huggingface/trl/pull/7890

### 🔀 X-Token cross-tokenizer distillation in GOLD

`GOLDTrainer` gets off-policy cross-tokenizer distillation based on [X-Token](https://huggingface.co/papers/2605.21699): set `lmbda=0.0` and `xtoken_loss_type="p_kl"` or `"h_kl"` with a precomputed projection matrix.

* Add X-Token cross-tokenizer KD to GOLD trainer by @kashif in https://github.com/huggingface/trl/pull/6126
* Support byte-fallback tokenizers (Gemma) in GOLD byte-offset alignment by @kashif in https://github.com/huggingface/trl/pull/8010

### 🟥 Training on AMD GPUs

TRL's trainers now run on AMD Instinct GPUs through PyTorch's ROCm build, with a [guide](https://huggingface.co/docs/trl/amd_gpus) and an AMD CI job that runs the test suite on every PR.

* Add AMD/ROCm CI by @kashif in https://github.com/huggingface/trl/pull/5918
